## 这是什么

墨林（MolinInk）是一个用 PHP 写的博客程序，跑在 Nginx 和 MySQL 上。

它的做法是把结构和功能分开。内核只负责地基：路由、模板渲染、数据库迁移、缓存、权限、媒体处理。写文章之外的事情都做成插件，友情链接、图片压缩、邮件订阅、统计这类，需要什么装什么，用不上就不装。页面的长相交给主题。所以程序本体很小，默认只带一个主题（`molin-default`）和一个发信插件（`mail-smtp`）。

适合的情况：自己有域名和服务器，愿意花二十分钟照着文档装一遍；需要一个中文界面、国内访问正常、数据完全握在自己手里的博客；不喜欢装完就多出几十个菜单、插件之间互相打架。

如果你的诉求只是"找个地方写文章、不想管服务器"，那静态博客（Hugo、Hexo 配 GitHub Pages）或者现成的托管平台会更省事 —— 墨林是要自己维护服务器的。

## 能做什么

**写内容**

- 文章、独立页面，以及自己定义的内容类型（想加"作品集""笔记"这类，字段可以自己加）
- 所见即所得的编辑器，不加载第三方富文本库；浏览器禁用了 JavaScript 时退回纯文本框，照样能写能存
- 文章状态五种：草稿、待审、私密、已发布、回收站；单篇文章可以设访问密码
- 修订历史，两次保存之间改了什么能对比出来
- 分类、标签、导航菜单
- 附件页：图片和文件可以直接拿到一个对外地址

**维护站点**

- 评论：回复、审核、标记垃圾，有新的待审会在仪表盘提示
- 媒体库：上传自动生成多种尺寸的缩略图，列页面不用拉原图
- 搜索
- `feed`（RSS/Atom）、`sitemap.xml`、`robots.txt`
- 用户、角色与能力：按能力点授权，不是只有"管理员 / 编辑"两档
- 备份与恢复（整站打包，可以下载到本地）、导入导出（`.json` / `.xml` / `.tar.gz`，只读数据，不执行代码）
- 站点健康检查（PHP 版本、必需与推荐扩展、PHP 配置、目录可写、数据表结构逐项列出）与运行日志

**扩展与集成**

- 主题是 Twig 模板加 CSS，不用写 PHP
- 插件通过钩子接到内核上，用到的能力在清单里声明
- REST 接口在 `/api/v1/`，可以给 App 或者脚本用
- 命令行入口 `php molin`，备份、迁移、建用户这些事可以写进脚本

界面有简体中文、繁体中文、英文三套，后台可以给单篇文章单独指定语言。

## 运行要求

| 项目 | 要求 | 说明 |
|---|---|---|
| PHP | 8.2 或更高 | 8.3、8.4 都可以 |
| 数据库 | MySQL 8.0+ 或 MariaDB 10.5+ | 字符集要用 `utf8mb4` |
| Web 服务器 | Nginx（推荐）或 Apache | 必须支持 URL 重写 |
| 磁盘 | 200 MB 起步 | 图片、备份另算 |

PHP 扩展：

| 扩展 | 做什么 | 缺了会怎样 |
|---|---|---|
| `pdo`、`pdo_mysql` | 连数据库 | 装不上 |
| `mbstring` | 中文等多字节字符处理 | 装不上 |
| `json` | 接口与缓存 | 装不上 |
| `openssl` | 加密与签名 | 装不上 |
| `fileinfo` | 判断上传文件的真实类型 | 装不上 |
| `zip` | 从后台上传安装主题/插件包 | 对应入口提示不可用 |
| `gd` 或 `imagick` | 生成图片缩略图 | 只存原图，列表页会变慢 |
| `intl` | 本地化的日期格式 | 日期退回默认格式 |
| `curl` | 备份上传到对象存储 | 该功能不可用 |

PHP 扩展不是 Composer 包，是 PHP 自带的功能模块。宝塔里在「软件商店 → PHP 8.x → 设置 → 安装扩展」勾选就行；命令行用 `php -m` 能看到已经装了什么。安装向导第一步就是逐项检查这些，缺哪项哪项变红，不用自己对照。

## 装起来

下面按宝塔面板写，用别的面板也差不多。顺利的话二十分钟以内。想先看看装完是什么样子：<https://demo.molinink.com>。

### 1. 准备

域名先解析到这台服务器。站点目录的属主是运行 PHP 的那个用户（宝塔建站默认就是 `www`），安装时要往站点根目录写 `config.php`、往 `storage/` 写缓存和日志，所以这两处需要可写。用别的面板时确认一下权限，不然向导会卡在写入那一步。

### 2. 建站点和数据库

宝塔「网站」→ 添加站点：填域名，PHP 版本选 8.2 以上，数据库选 MySQL。建完面板会给一套库名、用户名、密码，下一步要用，先记下来。

### 3. 上传解压

在 Releases 页下载 `molin-版本号.zip`（不要用仓库页面 `Code` 按钮下的源码包，原因见下面「下载哪个」）。进站点的文件管理，打开站点根目录（一般是 `/www/wwwroot/你的域名`），上传压缩包，右键解压到当前目录。

解压完根目录下应该能直接看到 `index.php`、`core/`、`install/` 这三样。如果多套了一层文件夹，进去全选剪切上来。

有个地方容易错：别用面板的「运行目录」去指那一层子目录。程序里 `/uploads/`、`/storage/` 这些路径规则都是按站点根写的，指偏了就不生效。

### 4. 配伪静态

程序只有一个入口文件，磁盘上并没有 `/admin` 这个文件，所以要让 nginx 把找不到的地址交给 `index.php`，否则文章页和后台都打不开。填到「设置 → 伪静态」：

```nginx
location / {
    try_files $uri $uri/ /index.php$is_args$args;
}

# 后台是程序路由，admin/ 目录里只有 css、js 和模板，没有 index 文件。
# 少了下面两行，nginx 会把它当目录，点「进入后台」是 403。
location = /admin {
    try_files $uri /index.php$is_args$args;
}
location = /admin/ {
    return 301 /admin;
}
```

Apache 用 `.htaccess`，内容随包在 `install/服务器配置.txt` 里。

### 5. 挡住 storage

`storage/` 里放的是备份包、日志和远端备份用的凭据，必须挡住，不然能被人直接下载。在「设置 → 配置文件」里，往 `server { }` 中间加：

```nginx
location ^~ /storage/ {
    return 404;
}
```

图片不用管，程序自己会输出。

### 6. 走向导

浏览器打开你的域名，点开始安装，一共五步：环境检测 → 数据库 → 站点与管理员 → 写入 → 完成。中途出错会整体回滚，不会留下装了一半的站。装完把 `install/` 删掉。

### 7. 核对四个地址

| 地址 | 应该是 |
|---|---|
| `你的域名/` | 首页能打开 |
| `你的域名/admin` | 后台登录页（404 说明伪静态没生效） |
| `你的域名/storage/backups/` | 404 |
| `你的域名/uploads/某张图片` | 能显示 |

带报错对照表的详细版随包在 `install/安装说明.txt` 里。

## 下载哪个

能直接装的是 Releases 里的包，文件名 `molin-版本号.zip`，依赖已经打进去了（`vendor/` 目录），解压就能用。

仓库页面绿色的 `Code` 按钮下的是源码，里面没有 `vendor/` —— 依赖由 Composer 安装，不往仓库里放。这样下下来直接访问，只会看到一行报错：

```
require(.../vendor/autoload.php): Failed to open stream
```

真要这么跑也可以，在站点根目录执行一次 `composer install --no-dev` 把依赖补上，后面的步骤一样。

另外说一句版本：仓库里的东西不一定是最新的。我平时在自己机器上改，隔一段时间才推上来，官网（<https://www.molinink.com>）上发布的才是实际发出去的版本。两边对不上以官网为准。

## 装完先做这几件事

1. **设置 → 站点**：站点名称、副标题、站点地址、时区、默认语言。站点地址写错了会影响后台生成的链接。
2. **设置 → 评论**：要不要先审核、允不允许匿名评论。
3. **外观 → 主题**：换主题、改主题设置（导航菜单、首页版块这类）。
4. **插件**：只启用真的会用的。启用得越多，页面加载和排查问题都越麻烦。
5. **工具 → 备份**：先跑一次备份，确认能生成、能下载。这一步花一分钟，后面能省很多事。
6. **账号**：把安装时设的管理员密码换成强一点的，别用 `admin` / `12345678`。

## 升级

后台「工具 → 更新」里有一套带体检的在线升级流程，但升级源还没对外开放，现在检查会提示拿不到清单，属正常。现阶段升级用手动覆盖：

1. 先备份：后台「工具 → 备份」跑一次，下载一份到本地。
2. 下载新版本的 `molin-版本号.zip`，解压到服务器上的临时目录。
3. 只覆盖程序文件。**保留** `config.php` 和 `storage/`（配置、上传的图片、备份全在里面）；自己装的主题和插件如果新包里没有，覆盖前先挪出来，覆盖完再放回去。
4. 新版本如果带了数据表结构变更，在站点根目录执行一次：

```bash
php molin db:migrate
```

   首次安装也是走这套迁移，安装和升级是同一条路，不会出现两边对不上的情况。
5. 清一下缓存（删掉 `storage/cache/` 里的内容即可，程序会重新生成），然后重走一遍上面那四个核对地址。

升级不会动 `config.php` 和 `storage/`，但覆盖之前还是建议先备份 —— 备份的成本远低于找回数据的成本。

## 备份与恢复

后台「工具 → 备份」会把数据库和文件打进一个包，可以下载到本地。恢复在同一个页面，也可以用命令行：

```bash
php molin backup:create     # 新建一份备份
php molin backup:list       # 看已有备份
php molin backup:restore    # 从备份恢复
```

搬站的时候连带 `config.php` 一起拷过去就行：数据库导出、`storage/uploads/` 拷过去、改 `config.php` 里的数据库信息。

## 目录结构

```
.
├── index.php      唯一入口，所有请求都从这里进
├── config.php     配置（安装时生成，不进版本库）
├── core/          内核：路由、模板、数据库、缓存、权限、媒体、迁移
├── admin/         后台界面（模板 + css/js）
├── themes/        主题，一个目录一个主题
│   └── molin-default/
├── plugins/       插件，一个目录一个插件
│   └── mail-smtp/
├── install/       安装向导，装完可以删掉
├── storage/       缓存、日志、上传、备份（不对外，必须挡住）
├── vendor/        依赖（安装包里已经带上）
└── molin          命令行入口
```

## 主题与插件

主题就是一个目录：模板（Twig）、CSS、静态资源、`theme.json` 清单。插件也是一个目录加一份清单，里面声明它用到哪些钩子和能力。想看最小可用的例子，直接读随包的 `themes/molin-default` 和 `plugins/mail-smtp`，结构就是照着它们的形状写的。

安装现成的：后台「外观 → 主题」或「插件」页上传 zip 包。写自己的：把目录放进去、在后台启用即可，改了模板刷新就生效。

内核里的钩子名是 `域/对象/阶段` 的形式（比如 `post/save/before`），能力点是 `域.动作`（比如 `post.create`）。这两套命名空间分开发、只增不改，所以插件在版本升级之后不会突然失效。

## 从源码跑

```bash
composer install --no-dev
cp config.example.php config.php   # 填上数据库信息
php molin install                  # 或者浏览器走向导
php -S 127.0.0.1:8000              # 本机看看效果
```

命令行工具都挂在 `php molin` 下，`php molin list` 能看到全部命令。

## 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打开是空白页或 500 | PHP 报错被藏起来了 | 看 `storage/logs/` 里的日志；确认 PHP 版本 ≥ 8.2、扩展齐全 |
| 首页正常，文章页 404 | 伪静态没配 | 回到第 4 步 |
| 点「进入后台」403 | 缺 `/admin` 那两段规则 | 同上 |
| 装到「写入」这一步失败 | 根目录或 `storage/` 不可写 | 把属主改回运行 PHP 的用户，或给目录写权限 |
| 连不上数据库 | 库名/用户/密码不对，或数据库只允许本机连 | 用面板给的凭据；数据库地址填 `127.0.0.1` 或 `localhost` |
| 提示没有建表权限 | 数据库用户只被授权了某个库 | 授权范围给 `库名.*`；装了通配授权（`%`、`_`）的版本能正确识别 |
| 图片显示不出来 | `uploads/` 不存在或被挡住 | 确认 `storage/uploads/` 有内容、`/uploads/` 没写进禁止规则 |
| 上传大图片失败 | PHP 的 `upload_max_filesize` / `post_max_size` 太小 | 调大这两个值，然后重启 PHP |
| 后台样式乱了 | 静态资源被 CDN 或缓存拦了 | 清缓存，确认 `/admin/` 路径能正常返回 css |
| 忘记管理员密码 | — | 站点根目录执行 `php molin user:password`，按提示设新密码 |
| 页面中文变成问号 | 数据库或连接字符集不是 `utf8mb4` | 改库和连接字符集为 `utf8mb4`，重新导入数据 |
